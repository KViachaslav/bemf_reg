# BEMF_reg — регулятор оборотов коллекторного мотора с BEMF-обратной связью

Прошивка для **STM32F103C8T6** (Blue Pill): управление щёточным коллекторным мотором
через ШИМ и одиночный logic-level MOSFET, измерение **обратной ЭДС (BEMF)** в
специально организованных паузах ШИМ — **без внешних датчиков**, ПИ-регулятор
оборотов, текстовый протокол команд/телеметрии по UART и набор защит.

Ключевая особенность этой версии (см. `popravka.md`): BEMF измеряется
**дифференциально двумя каналами ADC1**:

```
PA0 (ADC1_IN0) — низкая сторона мотора (V_low)
PA1 (ADC1_IN1) — питание мотора       (V_supply)

V_bemf = V_supply − V_low
```

Питание измеряется в каждом замере, поэтому **константа 12 В в коде не используется** —
просадка питания под нагрузкой компенсируется автоматически.

## 1. Возможности

| Функция | Реализация |
|---|---|
| ШИМ мотора | TIM1_CH1 (PA8), 20 кГц, скважность 5…95 % |
| Обратная связь | BEMF, дифференциальный замер ADC1 (2 канала) + DMA, раз в 20 мс |
| Регулирование | ПИ с anti-windup и мёртвой зоной, вызов 1 кГц (TIM2) |
| Интерфейс | USART1 115200 8N1: команды `S/K/R/X/?/C` + телеметрия раз в 100 мс |

| Защиты | stall, недостоверный BEMF, потеря UART, `SUPPLY_LOW`, `SENSOR_FAULT` |
| Индикация | LED PC13 (active low), при аварии мигает 5 Гц |

## 2. Аппаратная часть

### 2.1. Схема подключения

```
+12В ──────┬───────────────┐
           │               │
        [МОТОР]         [диод SR340]
           │            (катод к +12В)
           │               │
           ├───────► PA0 (ADC1_IN0) — низкая сторона мотора
           │          (делитель 10к/2к на GND)
           │
           ├── сток IRLZ44N
           │     исток → GND
           │     затвор ← PA8 (TIM1_CH1) через 100 Ом
           │
           └───► PA1 (ADC1_IN1) — плюс мотора (питание)
                  (делитель 10к/2к на GND)
```

**Почему дифференциально:** мотор питается от +12 В жёстко, а ШИМ коммутирует
**низкую сторону** через IRLZ44N. В паузе (ключ закрыт) мотор вращается по инерции,
и его ЭДС «висит» между +12 В и PA0 — одиночный замер PA0 относительно GND давал бы
`12 В − BEMF`, то есть был бы привязан к питанию. Разность `V_supply − V_low`
убирает эту привязку.

> **Плата варианта GRBL (§18).** На ней те же два делителя выведены на разъёмы
> grblHAL с перекрёстной разводкой — **выводы A0 и A1 пришлось поменять местами**.
> Прошивка это учитывает: в GRBL-сборке роли входов переставлены
> (`BEMF_ADC_CH_SWAP = 1`): низкую сторону измеряет `PA1`, питание — `PA0`
> (подробности и способ отключить — §18.7). UART-сборка остаётся прежней
> (`BEMF_ADC_CH_SWAP = 0`), её бинарник не меняется.

### 2.2. Пины

| Пин | Функция | Примечание |
|---|---|---|
| PA8 | TIM1_CH1 → затвор IRLZ44N | через резистор 100 Ом |
| PA0 | ADC1_IN0 | делитель 10к/2к, низкая сторона мотора (в GRBL-сборке — питание, §18.7) |
| PA1 | ADC1_IN1 | делитель 10к/2к, питание мотора, режим Analog (в GRBL-сборке — низкая сторона, §18.7) |
| PA9 / PA10 | USART1 TX / RX | USB-UART (CH340), 115200 8N1 |
| PA13 / PA14 | SWDIO / SWCLK | ST-Link V2 (JTAG-DP отключён: `NOJTAG`) |
| PC13 | LED | active low (на плате через резистор к +3.3 В) |
| GND | общий | **GND мотора и MCU обязательно объединить** |
| PB6 | TIM4_CH1 → вход ШИМ от grbl | **только вариант GRBL**: уставка оборотов по скважности, вход с pull-down (логика 3.3 В, делитель не нужен) — §18 |
| PB8 | вход разрешения вращения | **только вариант GRBL**: 1 — вращать, 0 — стоп; pull-down, поэтому обрыв провода = стоп — §18 |

### 2.3. Номиналы и компоненты

| Элемент | Значение | Зачем |
|---|---|---|
| MOSFET | IRLZ44N (logic-level) | коммутация низкой стороны без драйвера |
| Диод | SR340 (Шоттки) | гашение индуктивных выбросов мотора |
| R_затвор | 100 Ом | ограничение тока затвора |
| Делитель PA0 | 10 кОм / 2 кОм | масштаб до 19.8 В (12 В → 2.0 В) |
| Делитель PA1 | 10 кОм / 2 кОм | там же (номинал одинаков → масштаб одинаков) |
| UART | USB-UART CH340 | команды и телеметрия |
| Программатор | ST-Link V2 | прошивка/отладка по SWD |

Максимальное измеряемое напряжение при делителе 10к/2к и Uref = 3.3 В:
`3.3 В × 6 = 19.8 В`. Мотор до 12 В укладывается с запасом.

> Диод SR340 при паузе замыкает индуктивный ток мотора и держит `V_low ≈ −0.4 В`,
> пока ток не затухнет. Поэтому после выключения ключа обязательно выжидается
> `BEMF_SETTLE_US` (по умолчанию 1 мс); иначе замер `V_bemf = V_supply − V_low`
> выходит за допустимый диапазон и отбрасывается. При большой индуктивности
> (низкое R/L) это время нужно увеличить — см. §13.

## 3. Как это работает

### 3.1. Тайминги периферии

| Периферия | Настройка | Назначение |
|---|---|---|
| TIM1 | PSC = 0, ARR = 3199 @64 МГц → **20 кГц**, CCR1 = скважность | ШИМ мотора (PA8) |
| TIM2 | PSC = 63, ARR = 999 → **1 кГц** | тик ПИ-регулятора + защит |
| TIM3 | PSC = 63, ARR = 999 → **1 кГц** | счётчик до измерительной паузы |
| ADC1 | Scan: IN0(ранг 1) → IN1(ранг 2), SW-триггер, 71.5 такта | замер `V_low`/`V_supply` |
| DMA1_CH1 | Circular, halfword, MEM inc, `ADC1->DR → adc_dma_buf[2]` | доставка пары замеров |
| USART1 | 115200 8N1, RX по прерыванию | команды/телеметрия |
| DWT->CYCCNT | `SystemCoreClock` тактов/мкс | микросекундная пауза в ISR |

ADC тактируется от PCLK2/6 = **10.67 МГц** (предел для F1 — 14 МГц).
Одно преобразование = `(71.5 + 12.5) / 10.67 МГц ≈ 7.9 мкс`, скан из двух каналов
≈ 15.7 мкс.

### 3.2. Цикл замера (каждые 20 мс, в прерывании TIM3)

1. `motor_pwm_pause()` — CCR1 = 0, ключ IRLZ44N закрыт (таймер TIM1 продолжает
   считать, рабочая скважность сохранена).
2. Выдержка `BEMF_SETTLE_US` (1 мс) через DWT — затухание индуктивного выброса.
3. `HAL_ADC_Start_DMA()` — ADC1 сканирует IN0 → IN1, результат кладёт DMA1_CH1.
4. Ожидание готовности пары с ограничением `BEMF_DMA_GUARD_ITER`
   (20000 итераций ≈ 1.5 мс @64 МГц) — защита от зависания.
5. `motor_pwm_resume()` — ШИМ возвращается с прежней скважностью.
6. Проверки достоверности и пересчёт:
   * `raw_low` и `raw_supply` равны 0 **одновременно** → инкремент `sensor_streak`
     (признак обрыва измерительного тракта);
   * код «упёрся» в край шкалы (`≤1` или `≥4094`) на любом входе → замер отброшен,
     инкремент `invalid_streak`;
   * `V_bemf < −0.2 В` или `V_bemf > V_supply + 0.2 В` → замер отброшен;
   * иначе замер принят: `data_valid = 1`, `invalid_streak = 0`.
7. Скользящее среднее глубины `BEMF_AVG_DEPTH` (8) по `V_bemf` и по коду PA0.
8. `RPM = V_bemf × K_motor × BEMF_RPM_SIGN` (по умолчанию `K_motor = 100`,
   `BEMF_RPM_SIGN = +1`).

### 3.3. Стоимость измерительной паузы (осознанный компромисс)

Пауза (1 мс выдержки + ~16 мкс АЦП) занимает **≈ 1.02 мс из каждых 20 мс (~5 %)**, всё
это время:

* ШИМ выключен (средняя скважность падает примерно на 5 %, ПИ это компенсирует);
* прерывания с более низким приоритетом (TIM2 — ПИ и защиты) задерживаются на ~1 мс.

Приоритеты NVIC выбраны так, чтобы замер не разрушался:
`DMA1_CH1 = 0` > `TIM3 = 1` > `TIM2 = 2` > `TIM1_UP = USART1 = 3`, `SysTick = 15`.

## 4. Карта периферии и приоритеты

| Модуль | Периферия | IRQ / приоритет | Где инициализируется |
|---|---|---|---|
| `motor_pwm` | TIM1 CH1 | `TIM1_UP` preempt 3 | `MX_TIM1_Init()` + `motor_pwm_init()` |
| `pid` | TIM2 | `TIM2_IRQn` preempt 2 | `pid_init()` (в коде) |
| `bemf` | TIM3 + ADC1 + DMA1_CH1 + DWT | `TIM3_IRQn` preempt 1, `DMA1_Channel1_IRQn` preempt 0 | `bemf_init()` (в коде) |
| `uart_cmd` | USART1 | `USART1_IRQn` preempt 3 | `MX_USART1_UART_Init()` + `uart_cmd_init()` |
| `fault` | GPIOC (PC13) | тик из TIM2 | `fault_init()` |
| `pwm_in` (**только GRBL**) | TIM4 CH1 (PB6) + GPIOB (PB8) | `TIM4_IRQn` preempt 3 | `pwm_in_init()` (в коде; в UART-сборке модуль пуст) |

> ADC1 и DMA **не** инициализируются сгенерированными `MX_ADC1_Init()`/`MX_DMA_Init()` —
> они полностью настраиваются в `bemf_init()` (`.ioc` для них обновлён как
> документация). TIM2/TIM3 тоже создаются кодом. В GRBL-сборке кодом создаётся и
> TIM4 (захват входного ШИМ). Подробности и предупреждение о регенерации — в §6.

| `main.c` | HAL, часы (HSI→PLL 64 МГц), `MX_*_Init`, порядок инициализации модулей, главный цикл | `main`, `SystemClock_Config` |
| `stm32f1xx_it.c` | обработчики IRQ: `TIM2_IRQHandler`, `TIM3_IRQHandler`, `DMA1_Channel1_IRQHandler`, `USART1_IRQHandler` | — |

Порядок инициализации в `main()`:
`motor_pwm_init()` → `pid_init()` → `bemf_init()` → `fault_init()` → `uart_cmd_init()`,
затем баннер и бесконечный цикл с `uart_cmd_poll()`.

### 6.1. Требования

| Компонент | Версия / источник |
|---|---|
| STM32CubeIDE | 2.0.0 (в комплекте `arm-none-eabi-gcc` 13.3.rel1) |
| STM32Cube FW_F1 | V1.8.7 (папка `Drivers/` уже в проекте) |
| ST-Link | V2 (SWD) + драйвер |

Проект — **проект STM32CubeIDE** (`.project` / `.cproject`); `CMakeLists.txt` и
`Makefile` в нём нет, сборка выполняется IDE.

### 6.2. Порядок сборки

1. `File → Import… → General → Existing Projects into Workspace` → указать
   `c:\project\BEMF_reg` → Finish.
2. Конфигурация `Debug` (по умолчанию) → `Project → Build Project`.
3. Результат: `Debug/BEMF_reg.elf` (плюс `.hex`/`.bin`, если включено в настройках).

Ожидаемые размеры этой версии (измерено CLI-сборкой, см. §6.4):

```
Флаги:  -Wall -Wextra -O0, 0 warnings
FLASH:  ≈ 40 828 B  (≈ 64 % от 64 КБ)
RAM:    ≈  2 968 B  (≈ 15 % от 20 КБ)
```

### 6.3. ⚠️ Не перегенерируйте код из `.ioc`

`BEMF_reg.ioc` обновлён и поддерживается **как документация** конфигурации.
Регенерация через CubeMX (или «Generate Code» в IDE) **сломает сборку**, потому что:

* `MX_ADC1_Init()` и `MX_DMA_Init()` отсутствуют в `main.c` — ADC1 и DMA создаются
  в `bemf_init()`. Генератор добавит их заново (дублирующая инициализация);
* `DMA1_Channel1_IRQHandler` уже написан вручную в `stm32f1xx_it.c` — генератор
  добавит второй (конфликт линковки);
* TIM2/TIM3 (ПИ и планировщик пауз) вообще не описаны в `.ioc` — они создаются
  в `pid_init()` и `bemf_init()`.

Если конфигурация всё-таки менялась в CubeMX, переносите изменения в код вручную.

### 6.4. Проверка сборки без IDE (проверено вживую)

Сборку проекта можно воспроизвести напрямую компилятором из состава CubeIDE
(проверено на `gnu-tools-for-stm32 13.3.rel1`). Этот же скрипт удобно использовать
как быструю проверку «не сломал ли я код», когда IDE нет под рукой.

> **То же самое одной командой** — `_build\build_main.ps1` (проверено вживую:
> 0 предупреждений при `-Wall -Wextra`; вариант `uart` — `text=40392 data=484
> bss=2476`, вариант `grbl` — `text=44144 data=488 bss=2584`):
>
> ```powershell
> powershell -ExecutionPolicy Bypass -File _build\build_main.ps1              # вариант uart
> powershell -ExecutionPolicy Bypass -File _build\build_main.ps1 -Mode grbl   # вариант grbl
> powershell -ExecutionPolicy Bypass -File _build\build_all.ps1               # обе + firmware\
> ```
>
> Скрипт повторяет шаги ниже теми же флагами (`-Wall -Wextra -O0`) плюс
> `-DBEMF_CTRL_GRBL=<0|1>`, складывает результат в `_build\out\<вариант>\`
> (`BEMF_reg.elf`, `.bin`, `.hex`, `.map`; копия последней сборки — в `_build\out\`),
> печатает `arm-none-eabi-size` и проверяет, что `DMA1_Channel1_IRQHandler`,
> `TIM2_IRQHandler`, `TIM3_IRQHandler` попали в вектор, а не в `Default_Handler`
> (`TIM4_IRQHandler` в UART-сборке остаётся слабым `W`, в GRBL — наш `T`).
> Отличие от ручного прогона: список объектов уходит линкеру через
> response-файл (`@_build\out\<вариант>\objs.rsp`) с прямыми слэшами — PowerShell
> не искажает аргументы, и сборка воспроизводима независимо от версии консоли.
>
> **Регресс UART-варианта** — `_build\cmp_syms.ps1` сравнивает размеры **всех**
> символов двух ELF, поэтому видно не только `text`, но и любую случайно
> изменившуюся функцию:
>
> ```powershell
> powershell -ExecutionPolicy Bypass -File _build\cmp_syms.ps1 `
>   -A _build\out\uart\BEMF_reg.elf -B _build\out\grbl\BEMF_reg.elf -Out _build\sym_diff.txt
> ```
>
> Проверено на этом коммите: UART-сборка совпадает с предыдущей версией
> (`text=40392`) до байта — все 486 символов имеют те же размеры.
>
> Как воспроизвести эталонную сборку для сравнения: `git worktree add ..\_prev
> <предыдущий-коммит>`, в копии заменить `$ROOT` в `_build\build_main.ps1` на её
> путь и собрать — лог эталона лежит в `_build\build_head_ref.txt`.

```powershell
$ErrorActionPreference = 'Continue'
$TOOL = 'C:\ST\STM32CubeIDE_2.0.0\STM32CubeIDE\plugins\com.st.stm32cube.ide.mcu.externaltools.gnu-tools-for-stm32.13.3.rel1.win32_1.0.100.202509120712\tools'
$GCC  = "$TOOL\bin\arm-none-eabi-gcc.exe"
$NANO = "$TOOL\arm-none-eabi\lib\nano.specs"
$BEMF = 'c:\project\BEMF_reg'
Set-Location $BEMF

$DEFS  = '-DUSE_HAL_DRIVER','-DSTM32F103xB'
$INC   = '-ICore/Inc','-IDrivers/STM32F1xx_HAL_Driver/Inc','-IDrivers/STM32F1xx_HAL_Driver/Inc/Legacy','-IDrivers/CMSIS/Device/ST/STM32F1xx/Include','-IDrivers/CMSIS/Include'
$FLAGS = '-mcpu=cortex-m3','-mthumb','-Wall','-Wextra','-O0','-ffunction-sections','-fdata-sections','-std=gnu11','-c'

Remove-Item -Recurse -Force obj -ErrorAction SilentlyContinue
New-Item -ItemType Directory -Force -Path obj | Out-Null

# compile: Core/Src + HAL sources (27 files total)
$files = @(Get-ChildItem Core/Src/*.c) + @(Get-ChildItem Drivers/STM32F1xx_HAL_Driver/Src/*.c)
foreach ($f in $files) {
  & $GCC @DEFS @INC @FLAGS $f.FullName -o ("obj/" + $f.BaseName + ".o")
  if ($LASTEXITCODE -ne 0) { "FAILED: $($f.Name)" }
}

# link
$objs = (Get-ChildItem obj/*.o | ForEach-Object { $_.FullName })
& $GCC '-mcpu=cortex-m3' '-mthumb' "-T$BEMF\STM32F103C8TX_FLASH.ld" "-specs=$NANO" `
      '-Wl,--gc-sections' "-Wl,-Map=$BEMF\obj\app.map" @objs `
      "$BEMF\Core\Startup\startup_stm32f103c8tx.s" '-lc' '-lm' '-lnosys' `
      '-o' "$BEMF\obj\app.elf"

& "$TOOL\bin\arm-none-eabi-size.exe" obj/app.elf
```

```
RAM   = data + bss  =  2 968 B  (≈15 % от 20 КБ)
```

Проверить, что обработчики попали в вектор, а не в `Default_Handler`:

```powershell
& "$TOOL\bin\arm-none-eabi-nm.exe" obj/app.elf | Select-String 'DMA1_Channel1_IRQHandler|TIM3_IRQHandler'
# 08005e44 T DMA1_Channel1_IRQHandler   (не Default_Handler — значит вектор настроен)
```

> **Два подводных камня при ручном вызове из PowerShell:**
> 1. котируйте **каждый** аргумент (одинарные кавычки). Некотируемые
>    `-Tscript.ld`, `-specs=nano.specs`, `-Wl,--gc-sections` PowerShell передаёт
>    компилятору искажённо (символы `.`/`,` внутри токена), и линковка падает с
>    «cannot open linker script file» либо «cannot read spec file»;
> 2. в этом pack-е тулчейна `-specs=nano.specs` работает **только по абсолютному
>    пути**: по имени gcc ищет файл `nano` и не находит его. Поэтому пути к `.ld`
>    и к `nano.specs` в скрипте абсолютные — так он воспроизводимо проходит.
>
> Без `nano.specs` (полный newlib) сборка тоже линкуется, но больше по памяти:
> FLASH 55 040 B (~84 %), RAM 4 704 B (~23 %).

> Форматирование вывода целиком целочисленное (`%lu`, `%ld`, `%u`, `%03lu`) —
> вещественные значения заранее пересчитываются в целые (например, `VS=12.1V`
> печатается как `supply_x10/10` и `supply_x10%10`). Поэтому `%f`-вариант `printf`
> (`-u _printf_float`) не требуется, достаточно `nano.specs`.

### 7.1. Безопасное подключение ST-Link к отдельно питаемой плате

Плата может питаться от внешнего БП, а ST-Link служить только отладчиком. В этом
случае соединяйте **только сигнальные линии и землю, 3.3 В не подключайте**:

| Пин ST-Link | Куда | Обязательность |
|---|---|---|
| GND | GND платы | да, соединять **первым** |
| SWDIO | PA13 | да |
| SWCLK | PA14 | да |
| NRST | NRST | желательно (даёт аппаратный сброс по `-rst`) |
| 3.3 V | — | **нет**: у клонов ST-Link это выход LDO, он конфликтует с LDO платы |
| 5 V | — | **никогда** |

Правила и проверка «живости» без остановки ядра:

1. общий GND обязателен между платой, ST-Link и USB-UART адаптером;
2. питание мотора (12 В) на время SWD-сеанса держите выключенным;
3. проверка одним чтением с hot-plug — ядро не останавливается, прошивка
   не сбрасывается:

```powershell
$PROG = 'C:\Program Files\STMicroelectronics\STM32Cube\STM32CubeProgrammer\bin\STM32_Programmer_CLI.exe'
& $PROG -c port=SWD mode=hotplug -r32 0x2000040C 1
```

Ожидаемый вывод (проверено вживую):

```
Voltage     : 3.28V       <- 0.0V = нет GND / неверный пин / плата не питается
Device ID   : 0x410
Device name : STM32F101/F102/F103 Medium-density
Flash size  : 64 KBytes
Connect mode: Hot Plug
0x2000040C : 0001F6AE     <- uwTick (HAL_GetTick); число произвольное = аптайм
```

`0x2000040C` — адрес переменной `uwTick` в текущей сборке (`.bss.uwTick` из
`BEMF_reg.map`). Повторите команду через несколько секунд: значение увеличится
примерно на прошедшие миллисекунды — значит `HAL_Init`, `SystemClock_Config` и
SysTick работают. Адрес сверяйте по свежему `.map` (после правок кода он может
сместиться):

```powershell
& "$TOOL\bin\arm-none-eabi-nm.exe" _build\out\BEMF_reg.elf | Select-String 'uwTick'
# 2000040c b uwTick
```

`No debug probe detected` = программатор не виден в USB (занят другим процессом
либо не подключён). Режим connect-under-reset не нужен: SWJ удерживается
включённым через `__HAL_AFIO_REMAP_SWJ_NOJTAG()`, поэтому hot-attach проходит и
на уже работающей прошивке.

## 9. Протокол UART

Команды — строки ASCII, завершаются `\n` (или `\r\n`). Регистр не важен (кроме `?`).
Максимальная длина строки — 32 байта.

| Команда | Действие | Ответ |
|---|---|---|
| `S<rpm>` | задать уставку оборотов (0…6000), сброс интегратора | `OK SET=1500` |
| `K<kp>,<ki>` | задать коэффициенты ПИ | `OK K=0.5,0.1` |
| `R` | запуск мотора (скважность = 5 %) | `OK RUN` / `ERR FAULT ACTIVE, SEND X` |
| `X` | стоп мотора **и сброс аварии** | `OK STOP` |
| `?` | немедленный кадр телеметрии | кадр телеметрии |
| `C` | калибровка, шаг 1: прогон 1 с на 50 % ШИМ в открытом цикле, замер `V_bemf` | `OK CAL VBEMF=2.345 V, SEND C<rpm>` |
| `C<rpm>` | калибровка, шаг 2: пересчёт `K_motor` по показанию внешнего тахометра | `OK K=640.1` |
| `M0` | **только GRBL**: ручной режим — уставка и пуск/стоп с ПК (обход grbl) | `OK M0 UART MODE` |
| `M1` | **только GRBL**: вернуть управление grbl (ШИМ PB6 + разрешение PB8) | `OK M1 GRBL MODE` |
| `P<rpm>` | **только GRBL**: сколько оборотов соответствует скважности 100 % (согласование с `$30`) | `OK P=6000` |

В варианте `grbl` уставка приходит по ШИМ, поэтому команды `S`, `R` и `C` доступны
только после `M0`, иначе ответ `ERR GRBL MODE, SEND M0 FIRST`. Команды `X`, `?`,
`K`, `M0`, `M1`, `P` работают всегда. `X` в этом варианте дополнительно блокирует
автозапуск от PB8 до следующего фронта 0 → 1 (то есть до нового `M3` в grbl).

Ошибки разбора: `ERR UNKNOWN CMD`, `ERR FORMAT K<kp>,<ki>`,
`ERR FAULT ACTIVE, SEND X`, `ERR STOP MOTOR FIRST (X)`,
`ERR NO CAL DATA, SEND C FIRST`, `ERR FAULT DURING CAL`.

**Телеметрия** (каждые 100 мс и по `?`), формат варианта `uart`:

```
RPM=1502 SET=1500 DUTY=45.3% ERR=-2 ADC=1234 VS=12.1V FLT=0
```

Формат варианта `grbl` — тот же, плюс состояние входа управления (PB6/PB8):

```
RPM=1502 SET=1500 DUTY=45.3% ERR=-2 ADC=1234 VS=12.1V PWM=25.00% F=1000 EN=1 FLT=0
```

| Поле | Смысл |
|---|---|
| `RPM` | обороты, рассчитанные по BEMF (`V_bemf × K_motor × sign`) |
| `SET` | текущая уставка, RPM |
| `DUTY` | скважность ШИМ, % (с точностью 0.1 %) |
| `ERR` | `SET − RPM`, со знаком |
| `ADC` | скользящее среднее кода АЦП **низкой стороны** (PA0), 0…4095 |
| `VS` | измеренное **питание мотора** (PA1), в вольтах с одним знаком |
| `FLT` | код аварии (см. §12): `0` — норма |
| `PWM` | **только GRBL**: скважность входного ШИМ (PB6) в процентах с двумя знаками; `0.00` — сигнала нет (тишина или < 1 %) |
| `F` | **только GRBL**: частота входного ШИМ, Гц (0 — сигнала нет) |
| `EN` | **только GRBL**: уровень на PB8: `1` — grbl разрешил вращение, `0` — стоп |

> Пока мотор остановлен, замеры не выполняются (ЭДС отсутствует), поэтому
> `RPM=0 ADC=0 VS=0.0V`. Значение `VS` появляется только при работающем моторе.

## 10. Калибровка `K_motor`

`RPM = V_bemf × K_motor` — зависимость ЭДС от оборотов у каждого мотора своя, поэтому
перед первым запуском в замкнутом контуре **обязательно** выполните калибровку.
По умолчанию в прошивке `K_motor = 100.0` (грубое значение).

Порядок:

1. Убедитесь, что аварии нет (`FLT=0`) и мотор остановлен.
2. Отправьте `C`. Прошивка:
   * отключает ПИ (открытый цикл) и сбрасывает интегратор;
   * запускает мотор на 50 % ШИМ (`UART_CMD_CAL_DUTY = 1600` из 3200) на 1 с;
   * по окончании измеряет `V_bemf`, останавливает мотор, возвращает замкнутый контур;
   * отвечает, например: `OK CAL VBEMF=2.345 V, SEND C<rpm>`.
3. Измерьте обороты внешним тахометром/стробоскопом и отправьте `C<rpm>`,
   например `C4980` (для 4980 RPM).
4. Прошивка считает `K_motor = RPM_эталон / V_bemf` и ответит `OK K=2123.6`.
5. Проверьте: `S1000`, `R` — в телеметрии `RPM` должен подтянуться к 1000.

> `K_motor` хранится **только в RAM** — после сброса питания восстанавливается
> значение по умолчанию. Для постоянного хранения впишите полученное число в
> `BEMF_K_MOTOR_DEFAULT` (`Core/Inc/bemf.h`) и пересоберите проект.

Если направление вращения инвертировано, измените знак `BEMF_RPM_SIGN` в `bemf.h`.

## 11. Настройка ПИ-регулятора

| Параметр | Значение по умолчанию | Где задаётся |
|---|---|---|
| `Kp` | 1.5 (подобрано на стенде) | `PID_KP_DEFAULT` / команда `K<kp>,<ki>` |
| `Ki` | 0.6 (подобрано на стенде) | `PID_KI_DEFAULT` / команда `K<kp>,<ki>` |
| период | 1 мс (`PID_DT_SECONDS = 0.001`) | TIM2 |
| мёртвая зона | 20 RPM (выход не меняется) | `PID_DEADBAND_RPM` |
| ограничение интегратора | ±12000 (anti-windup) | `PID_INTEGRAL_MAX` |
| диапазон выхода | 160…3040 (5…95 % ШИМ) | `MOTOR_PWM_DUTY_MIN/MAX` |
| ограничение уставки | 0…6000 RPM | `PID_SETPOINT_MAX_RPM` |

> `Kp`/`Ki` подобраны на стенде (мотор 775, `K_motor = 330`, 12 В): при `K1.5,0.6`
> уставки 300…2000 об/мин отрабатываются плавно, без перерегулирования и раскачки
> (`Kp = 2.5` уже даёт колебания оборотов ±10 %). Логи — `_uart_test/motor_t*.txt`,
> `motor_stress.txt`.
>
> `PID_INTEGRAL_MAX` должен покрывать весь диапазон скважности: `Ki · I_MAX ≥
> MOTOR_PWM_DUTY_MAX` (при `Ki = 0.25` это 12160). Значение 2000 из первой версии
> упиралось в 500 отсчётов (15.6 % ШИМ) и не давало выйти выше ~600 об/мин
> (см. README §16). Ограничения интегратора по `±I_MAX` и «вычитание избытка»
> работают совместно: первое задаёт запас, второе мгновенно снимает перегруз.

Anti-windup реализован «вычитанием избытка»: если рассчитанный выход вышел за
`DUTY_MIN/DUTY_MAX`, он насыщается, а из интегратора вычитается избыток, делённый
на `Ki` (интегратор встаёт в значение, при котором выход ровно на границе).

> **Найдено и исправлено на стенде (12 В + мотор).** В первой версии при
> насыщении отменялось целиком последнее приращение интегратора. У нижней границы
> (5 % ШИМ) это обнуляло накопление, и ПИ залипал на минимальной скважности:
> уставка `S300` давала `DUTY=5.0 %` и `ERR=293`, которые не менялись минутами
> (P-член `0.35·293 = 103` меньше `DUTY_MIN = 160`, а интегратор набрать не мог).

Порядок подбора (метод Циглера–Николса или вручную):

1. `Ki = 0` (`K0.5,0`), плавно увеличивайте `Kp` до появления автоколебаний уставки;
2. уменьшите `Kp` примерно вдвое, затем добавляйте `Ki` до приемлемого времени выхода
   без перерегулирования;
3. значения можно менять на ходу командой `K…` — перезагрузка не нужна
   (переменные защищены критической секцией);
4. для фиксации впишите подобранные значения в `Core/Inc/pid.h`.

Учтите: контур работает на данных BEMF, которые обновляются раз в 20 мс и усредняются
по 8 замерам, поэтому «звонкий» ПИ с большим `Kp` вызовет колебания скважности.

## 12. Защиты (fault)

Все проверки выполняются в тике 1 мс (TIM2) **только при работающем моторе**
(`motor_is_running() != 0`). При срабатывании: ШИМ = 0, интегратор ПИ сброшен, LED PC13
мигает 5 Гц. Дополнительные аварии не «перезаписывают» уже зафиксированный код —
приоритет у того, что обнаружено первым.

| Код | Имя | Условие | Как воспроизвести |
|---|---|---|---|
| 0 | `NONE` | аварии нет | — |
| 1 | `STALL` | уставка > 500 RPM и (`RPM` < 100 **или** есть отброшенные замеры) непрерывно 500 мс | заклинить вал при `S2000` |
| 2 | `BEMF_INVALID` | ≥ 3 недостоверных замера подряд при уставке ≤ 500 RPM | упор кода АЦП в 0/4095 (обрыв/КЗ делителя), но не заклинивание |
| 3 | `UART_LOST` | нет команд с ПК > 5000 мс | `S1000`, `R`, затем молчать 5 с |
| 4 | `SUPPLY_LOW` | `V_supply < 6.0 В` (после первого достоверного замера) | снизить питание мотора ниже 6 В при `R` |
| 5 | `SENSOR_FAULT` | код АЦП обоих входов (PA0 **и** PA1) равен 0 три замера подряд | отсоединить оба делителя от пинов |
| 6 | `PWM_LOST` | **только GRBL**: PB8 = 1 (grbl требует вращения), а фронтов на PB6 нет дольше 500 мс | выдернуть провод ШИМ от grbl при активном `M3` |

Порядок проверок в `fault_isr_1ms()`: `PWM_LOST (GRBL) → SENSOR_FAULT →
SUPPLY_LOW → STALL → BEMF_INVALID → UART_LOST (UART)`. Проверка питания поэтому не
может «перебить» диагноз обрыва измерительного тракта.

**Тишина на входе = стоп, а не авария.** Если фронтов на PB6 нет («молчит» линия ШИМ)
или скважность < 1 %, привод просто останавливается — так отрабатываются `M5`/`S0`
от grbl и режим удержания нуля (`$34=0`, скважность 0 не даёт фронтов). Код `PWM_LOST`
выставляется только тогда, когда при этом PB8 **всё ещё** требует вращения — это уже
признак обрыва управляющего провода или отказа grbl. Авария снимается сама, как
только сигнал вернулся, а также командой `X` или новым фронтом PB8 (0 → 1).

**Сброс аварии:** команда `X` (стоп + `fault_clear()`), затем `R` для перезапуска.
Прочие команды (`S`, `K`, `C`) при активной аварии отвергаются:
`ERR FAULT ACTIVE, SEND X`.

Особенности, о которых важно помнить при эксплуатации:

* Авария `UART_LOST` — это «сторожевой таймер» связи: **пока мотор работает, посылайте
  любую команду не реже 1 раза в 5 с** (удобно периодически отправлять `?`).
  Телеметрия, идущая от платы, таймер **не** сбрасывает. В варианте `grbl` этого
  сторожа нет (ПК к приводу может быть вообще не подключён) — его роль выполняет
  проверка `PWM_LOST` по линиям PB6/PB8.
* LED при `FLT=0` погашен (он горит/мигает только при аварии).

## 14. Ограничения и осознанные компромиссы

| Ограничение | Причина / следствие |
|---|---|
| Измерительная пауза ~1 мс раз в 20 мс | ШИМ на это время выключен (~5 % средней скважности) и ПИ задерживается на ~1 мс. Принято в ТЗ; при необходимости уменьшайте `BEMF_SETTLE_US` или увеличивайте период замера |
| Нет внешнего кварца | HSI 8 МГц → PLL ×16 = 64 МГц; точность частоты ±~1 % (влияет на реальные обороты, но не на работу ШИМ) |
| USB-периферия не используется | при HSI USB-часы недоступны |
| `K_motor` и `Kp/Ki` не сохраняются в FLASH | после сброса — значения по умолчанию; для фиксации правьте `#define` |
| Работа только с одним направлением вращения | знак задаётся `BEMF_RPM_SIGN` |
| Скважность ограничена 5…95 % | 100 % не оставляет пауз для BEMF, ниже 5 % мотор не крутится |
| Точность RPM — косвенная (по ЭДС) | на малых оборотах/нагрузке ЭДС мала, погрешность выше; калибровка обязательна |
| UART — единственный источник команд | потеря связи при работающем моторе = авария `UART_LOST` через 5 с |

## 15. Порядок первого запуска (чек-лист)

| Шаг | Что сделать | Ожидаемый результат |
|---|---|---|
| 1 | Собрать и прошить (см. §6–§7), подключить UART | в терминале баннер `BEMF_reg ready` |
| 2 | Отправить `?` | `... FLT=0`, раз в 100 мс идут кадры телеметрии |
| 3 | **ШИМ без мотора:** осциллограф на PA8, отправить `C` | 20 кГц, 50 % скважности ~1 с, затем `OK CAL VBEMF=... V` |
| 4 | **Мотор без ОС:** `C` с подключённым мотором | мотор уверенно крутится на 50 %, MOSFET не греется |
| 5 | **Проверка питания:** при `C`/`R` смотреть `VS` | `VS` ≈ напряжение БП (напр. `12.1V`), под нагрузкой видна просадка |
| 6 | **Калибровка:** `C`, замерить обороты тахометром, `C<rpm>` | `OK K=...`, затем `S1000`, `R` — `RPM` ≈ 1000 |
| 7 | **Настройка ПИ:** `K<kp>,<ki>`, `S1000`, `R` | выход на уставку без перерегулирования (см. §11) |
| 8 | **Стресс:** `S500` → `S2000` → `S500` | отработка без аварий и затяжных колебаний |
| 9 | **Fault-тесты:** заклинить вал при `S2000`; отключить делитель PA0/PA1; снизить питание <6 В; молчать 5 с | `FLT=1`, `FLT=5`, `FLT=4`, `FLT=3` соответственно |
| 10 | Сброс аварии `X` → `R` | `OK STOP`, затем `OK RUN`, `FLT=0` |
| 11 | Зафиксировать подобранные `K_motor`, `Kp`, `Ki` в `#define` и пересобрать | значения «выживают» сброс питания |

> **Управлять мотором удобнее пультом в браузере** — `_uart_test\motor_control.html`
> (в Chrome/Edge достаточно открыть файл двойным щелчком: локальные файлы считаются
> доверенным контекстом; если браузер старый — поднять
> `powershell -ExecutionPolicy Bypass -File _uart_test\serve_motor_control.ps1`
> и открыть `http://localhost:8099/`): пульт сам держит keep-alive `?`,
> показывает RPM/SET/DUTY/ERR/ADC/VS/FLT и график RPM, сохраняет журнал в файл.
> Консольная альтернатива — `_uart_test\read_uart.ps1` с `-TimedCmds`
> (подробности — `_uart_test/README.md`).

> **Уже проверено вживую на стенде без мотора** (плата от внешнего БП, ST-Link по
> SWD + CH340 по UART): шаги 1–2 (по сбросу — `BEMF_reg ready`, далее кадр
> `RPM=0 SET=0 DUTY=0.0% ERR=0 ADC=0 VS=0.0V FLT=0` каждые ~100 мс) и шаг 10.
> Дополнительно подтверждены: `S1500` → `OK SET=1500` (в телеметрии `SET=1500`,
> `ERR=1500`), `K1.5,0.1` → `OK K=1.5,0.1`, `K` без аргумента →
> `ERR FORMAT K<kp>,<ki>`, `Z` → `ERR UNKNOWN CMD`, `R` при пустом стенде →
> `OK RUN`, затем `FLT=2` с отключением ШИМ (см. §16), `X` → `OK STOP` и
> `FLT=0`. Шаги 3–9 требуют подключённого мотора, питания 12 В и осциллографа.
> Лог-файлы захватов UART — в `_uart_test/`.
>
> **Стенд с мотором 775 «12-36 В, 4000-12000 об/мин», питание 12 В, БП с лимитом 3 А —
> пройдены шаги 3–9 и 11** (логи `_uart_test/motor_*.txt`):
> шаг 3–4 — `C` (50 % ШИМ, 1 с) проходит штатно: `OK CAL VBEMF=5.20 V` (при лимите
> тока 1 А был честный `FLT=4` из-за просадки БП — см. §16);
> шаг 5 — `VS` = 12.1 В при работающем ШИМ, просадка видна прямо в телеметрии;
> шаг 6 — `C` + `C1715` → `OK K=329.7`, т.е. `K_motor ≈ 330` (паспорт мотора:
> 4000 об/мин при 12 В);
> шаг 7 — подобраны `Kp = 1.5`, `Ki = 0.6` (при `Kp = 2.5` — раскачка оборотов),
> лимит интегратора поднят до 12000; `S300` держится в мёртвой зоне (280 об/мин,
> ШИМ 11.5 %);
> шаг 8 — ступени `S1500` (773 → 1251 об/мин плавно) и `S2000` (1881 об/мин, ШИМ 52 %)
> без аварий и перерегулирования;
> шаг 9 — `FLT=3` (молчание ПК > 5 с → ШИМ снят, `X` снимает), `FLT=2` и `FLT=4`
> воспроизводились ранее;
> шаг 11 — `K_motor = 330`, `Kp = 1.5`, `Ki = 0.6`, `PID_INTEGRAL_MAX = 12000`
> зафиксированы в `#define` (`bemf.h`, `pid.h`), прошивка пересобрана и залита.
>
> Не выполнены (нужны приборы/руки): осциллограмма PA8 (шаг 3), `FLT=1` (заклинить
> вал при `S2000`), `FLT=5` (отключить делитель PA0/PA1).
>
> По ходу этой проверки найдены и исправлены **три ошибки в боевой прошивке**
> (подробности в §16): тип буфера DMA (`bemf.c`), анти-виндап ПИ и слишком малый
> лимит интегратора (`pid.c`).

## 16. Диагностика

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| **`FLT=2` сразу после `R` с подключённым мотором и питанием 12 В, `ADC=0 VS=0.0V`** *(ошибка, исправлена)* | буфер DMA ADC был объявлен `uint32_t[2]`, а DMA1 Channel1 настроен на полуслова: пара отсчётов (PA0, PA1) упаковывалась в `adc_dma_buf[0]`, а `adc_dma_buf[1]` всегда оставался нулём → `raw_supply = 0` → каждый замер браковался (`invalid_streak` растёт, `data_valid = 0`) | исправлено в `bemf.c`: буфер `uint16_t[2]` (тип по размеру элемента DMA). Проверено дампом ОЗУ по SWD: `adc_dma_buf` содержал `09CC09BC` = 2492/2508 |
| **`DUTY` залипает на 5 % и `ERR` не меняется** *(ошибка, исправлена)* | анти-виндап ПИ отменял целиком последнее приращение интегратора: у нижней границы (5 % ШИМ) накопление обнулялось, а P-член `0.35·err` меньше `DUTY_MIN` (например `S300`: `0.35·293 = 103 < 160`) | исправлено в `pid.c`: вычитание **избытка**, делённого на `Ki` (см. §11). Проверено: `S300` → ШИМ 5.2 → 17.3 %, `RPM` 5 → 150 |
| **`DUTY` выходит на плато и не растёт** (напр. 17.3 % при `S300`, 29 % при `S1500`), `ERR` остаётся большим *(исправлено)* | интегратор упирался в `PID_INTEGRAL_MAX = 2000`: вклад I-члена был ограничен `Ki·2000 = 500` отсчётов (15.6 % ШИМ), поэтому уставки выше ~600 RPM не достигались | в `pid.h` лимит увеличен до 12000 (правило: `Ki · I_MAX ≥ MOTOR_PWM_DUTY_MAX`). Проверено: `S2000` → 1881 RPM при ШИМ 52 % |
| **`FLT=4` при `C`/`R` с мотором на 50 % ШИМ** | реальная просадка питания: пусковой ток мотора превышает лимит БП (в момент аварии в буфере DMA было `V_supply = 4.55 В`) | поднять лимит тока БП, взять БП мощнее, добавить электролит параллельно питанию мотора; прошивка здесь сработала верно (ШИМ снят) |

| Нет баннера/телеметрии | нет общего GND, скорость/формат не 115200 8N1, TX/RX не перекрёстно, плата не запущена | проверить проводку, `LED` (не мигает = аварии нет), сброс платы |
| `FLT=5` | обрыв/непропай делителей или GND, PA1 не в режиме Analog, неподключённый UART-адаптер | проверить пайку обоих делителей, режим PA1, что ADC не «висит в нуле» |
| `FLT=4` | питание мотора < 6 В, слабый БП (просадка при пуске), неисправен делитель PA1 | поднять/усилить питание, контролировать `VS`, проверить делитель PA1 |
| `FLT=1` (stall) при живом моторе | `K_motor` не откалиброван (RPM занижен < 100), либо вал действительно заторможен, либо вал крутится, но замеры отбрасываются | сначала калибровка `C` + `C<rpm>`, затем проверить нагрузку |
| `FLT=2` | код АЦП на краю шкалы — обрыв/КЗ делителя, мотор заклинен при малой уставке | проверить измерительный тракт; при заклинивании это ожидаемо |
| `FLT=2` сразу после `R`, если мотор не подключён, а питание 12 В выключено (`ADC=0 VS=0.0V`) | входы PA0/PA1 висят в нуле/на краю шкалы — на «пустом» стенде это ожидаемое поведение | проверено вживую: так защита и аварийное отключение ШИМ подтверждаются без мотора; `X` снимает аварию, с подключённым мотором и питанием `R` запускается штатно |
| `FLT=3` | ПК молчит > 5 с при работающем моторе | периодически слать `?` или любую команду |
| `FLT=6` (вариант GRBL) | PB8 = 1, но фронтов на PB6 нет дольше 500 мс: обрыв провода ШИМ, grbl выключен/в аварии, либо в grbl идёт `M3 S0` (разрешение включено, скважность нулевая) | проверить провод PB6 и общий GND, посмотреть `PWM=`/`F=`/`EN=` в телеметрии; для остановки шпинделя использовать `M5`, а не `S0` |
| Мотор не вращается, в телеметрии `EN=0` | grbl не включил шпиндель (`M3`/`M4` не выполнялись) либо PB8 не подключён (pull-down держит «стоп») | выполнить `M3 S1500`, проверить провод PB8 и общий GND |
| `PWM=0.00% F=0`, `EN=1` | линия ШИМ молчит: обрыв/не тот вывод grbl (`spindlePWM`), скважность 0 | проверить подключение PB6 и настройки `$$` (§18) |
| `SET` не меняется при изменении `S` в grbl | уставка берётся из скважности, шкала задана командой `P` и не согласована с `$30`/`$36` | задать `P` = `$30` (по умолчанию 6000) и `$36` ≤ 95 |
| Шпиндель крутится на полную при `M5` | `$34=100` (в «стопе» grbl держит линию в 1) при неподключённом PB8 | `$34=0` и подключить PB8 (§18) |
| `RPM=0`, хотя мотор крутится | `K_motor` мал/не откалиброван; перепутан знак; замеры отбрасываются (диод шунтирует дольше `BEMF_SETTLE_US`) | калибровка, `BEMF_RPM_SIGN`, увеличить `BEMF_SETTLE_US` |
| `RPM` нестабилен, `DUTY` дёргается | шум замеров, слишком большой `Kp` | уменьшить `Kp`, увеличить `PID_DEADBAND_RPM`, увеличить `BEMF_AVG_DEPTH` |
| Мотор не крутится после `R` | вышел за 5…95 % ШИМ, неисправен ключ/затвор, нет питания мотора | осциллографом проверить PA8, `VS`, ключ |
| LED мигает 5 Гц | активна авария | смотреть `FLT` в телеметрии, устранить причину, `X` → `R` |
| Команды отвергаются: `ERR FAULT ACTIVE, SEND X` | активная авария | устранить причину, затем `X`, затем `R` |
| Телеметрия «замерла» на ~1 с | это команда `C`: главный цикл занят прогоном калибровки | нормальное поведение |
| Телеметрия «замерла» навсегда | авария без сброса? нет питания? | `?`, затем `X` → `R`; проверить питание |

Отличия реализации от буквы `task.md` (осознанные, зафиксированы в коде):

* TIM1 Update-прерывание не используется: планировщик замеров — TIM3 (1 мс), а не
  счётчик периодов ШИМ;
* TIM2/TIM3 и ADC1/DMA создаются в коде (`pid_init()`, `bemf_init()`), а не
  сгенерированными `MX_*_Init()`;
* введена «мёртвая зона» ПИ (`PID_DEADBAND_RPM`) и проверка `data_valid` перед
  контролем питания;
* в телеметрию добавлено поле `VS` (измеренное питание) — оно и есть практическая
  ценность дифференциальной схемы;
* лимит интегратора ПИ увеличен с 2000 до 12000: `Ki · I_MAX` обязан покрывать
  диапазон скважности (`MOTOR_PWM_DUTY_MAX`), иначе уставки выше ~600 RPM
  недостижимы (проверено на стенде, см. §11 и §16);
* значения `K_motor = 330`, `Kp = 1.5`, `Ki = 0.6` — результат калибровки и подбора
  на конкретном моторе 775 (шаги 6, 7, 11 чек-листа);
* сверх ТЗ добавлен **второй вариант сборки** (`grbl`, §18) — шпиндельный привод для
  grblHAL (ШИМ → PB6, разрешение → PB8) при неизменном поведении варианта `uart`:
  его ELF совпадает с предыдущей версией до байта (проверено `_build\cmp_syms.ps1`).

## 18. Вариант сборки GRBL (шпиндель для grblHAL)

Второй вариант той же прошивки превращает плату в **шпиндельный привод для grblHAL**:
уставка оборотов приходит скважностью внешнего ШИМ, пуск/стоп — уровнем разрешения.
Исходники общие, различия включены макросом `BEMF_CTRL_GRBL`
(`Core/Inc/ctrl_mode.h`) и задаются только ключом компилятора:

```powershell
powershell -ExecutionPolicy Bypass -File _build\build_main.ps1              # uart (по умолчанию)
powershell -ExecutionPolicy Bypass -File _build\build_main.ps1 -Mode grbl   # grbl
powershell -ExecutionPolicy Bypass -File _build\build_all.ps1               # обе + firmware\
```

### 18.1. Подключение к плате grblHAL

```
grblHAL (любой МК)                 BEMF_reg (эта плата)
spindlePWM (например PA8)  ─────►  PB6  (TIM4_CH1, вход, pull-down)
spindle enable             ─────►  PB8  (вход разрешения, pull-down)
GND                        ──────  GND   (обязательно общий!)
```

| Шаг | Что сделать |
|---|---|
| 1 | Соединить `spindlePWM` → `PB6`, `spindle enable` → `PB8`, **GND → GND** |
| 2 | Обе платы работают логикой 3.3 В — согласование уровней не нужно; при длинном проводе добавить последовательно 1 кОм и/или экран |
| 3 | Проверить настройки grblHAL (18.2) |
| 4 | Прошить `firmware\BEMF_reg_grbl.hex` (§7) |

### 18.2. Настройки grblHAL (`$$`)

| Параметр | Значение | Почему |
|---|---|---|
| `$30` | 6000 | максимальные обороты = уставке при скважности 100 %; совпадает с `P` (по умолчанию 6000) |
| `$31` | 0 | привод всё равно ограничен снизу: скважность < 1 % = «стоп» |
| `$32` | off | режим лазера не нужен |
| `$33` | 1000 Гц | паспортная частота ШИМ шпинделя; допустимый вход ≈ 61 Гц … 250 кГц |
| `$34` | **0** | скважность «стоп». При `$34=100` grbl в останове держит линию в 1, и без PB8 мотор будет крутиться |
| `$35` | 0 | инверсия не нужна (вход работает по положительной логике) |
| `$36` | 100, лучше ≤ 95 | скважность, соответствующая `$30`; при 100 % нет измерительных пауз BEMF |

### 18.3. Как это работает

* **PB6 (TIM4_CH1, захват).** Полярность переключается в прерывании «фронт → спад →
  фронт», поэтому хватает одного канала: `высокий = t(спад) − t(фронт)`,
  `период = t(фронт_N) − t(фронт_N−1)`, `скважность[%] = высокий × 100 / период`.
  Тик 250 нс (PSC = 15): при 1 кГц это 0.025 % скважности (≈1.5 об/мин при 6000).
  Аппаратный фильтр входа (8 замеров по 4 МГц) убирает иголки. Если спад не пришёл
  (линия зажата в 1) — скважность считается 100 %.
* **Уставка.** `SET = P × скважность / 100`, где `P` — команда `P<rpm>` (по умолчанию
  6000). Пересчёт раз в 50 мс, уставка обновляется при изменении > 10 RPM, интегратор
  ПИ при этом **не** сбрасывается — это плавное слежение за `S` в G-коде.
* **Пуск/стоп.** PB8 = 1 и валидная скважность ≥ 1 % → `pid_reset()` + `motor_start()`.
  PB8 = 0 → немедленный стоп. Обрыв провода PB8 (pull-down) = «стоп».
* **Тишина на PB6** (> 200 мс) или скважность < 1 % = стоп: так отрабатываются `M5` и
  `S0` (при `$34=0` скважность 0 не даёт фронтов). Если при этом PB8 = 1, через 500 мс
  фиксируется `FLT=6` (§12) — снимается сам при возврате сигнала, командой `X` или
  новым фронтом PB8.
* **Восстановление без консоли.** Фронт PB8 (0 → 1, то есть новый `M3`) снимает
  блокировку `X` и сбрасывает аварию — станку с одним grbl консоль не нужна.
* **Пока `FLT ≠ 0`, автозапуск от PB8 заблокирован** (привод стоит до сброса аварии).

### 18.4. Ручное вмешательство с ПК

По USART1 (115200 8N1) всегда доступны `?`, `X`, `K<kp>,<ki>`, `M0`, `M1`, `P<rpm>`;
`s`, `R`, `C` — только после `M0`:

```
M0       -> OK M0 UART MODE   (привод остановлен, управление с ПК)
S1500    -> OK SET=1500
R        -> OK RUN
X        -> OK STOP           (стоп + запрет автозапуска до нового M3)
M1       -> OK M1 GRBL MODE   (управление снова у grbl)
P6000    -> OK P=6000         (скважность 100 % = 6000 об/мин)
```

### 18.5. Проверка на стенде (без платы grblHAL)

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Подать на PB6 меандр 1 кГц / 25 % (генератор), **общий GND** | в телеметрии `PWM=25.00% F=1000` |
| 2 | Подать 3.3 В на PB8 | `EN=1`, `SET=1500`, мотор выходит на ~1500 RPM |
| 3 | Изменить скважность на 50 % | `SET=3000`, обороты растут плавно (без сброса интегратора) |
| 4 | Снять 3.3 В с PB8 | мгновенный стоп, `EN=0` |
| 5 | Вернуть PB8, отключить меандр | через ~0.2 с стоп, через ~0.5 с `FLT=6` и мигание LED |
| 6 | Вернуть меандр | авария снимается автоматически, мотор снова вращается |
| 7 | `X` при работающем grbl | стоп, автозапуск только после `M5` → `M3` |

### 18.6. Что попадает в сборку

| Элемент | UART (`BEMF_CTRL_GRBL=0`) | GRBL (`BEMF_CTRL_GRBL=1`) |
|---|---|---|
| `Core/Src/pwm_in.c` | пустая единица трансляции | драйвер входа (TIM4 + PB8) |
| `TIM4_IRQHandler` | слабый `W` из startup | наш `T`, приоритет 3 |
| Команды | `S`, `K`, `R`, `X`, `?`, `C` | `K`, `X`, `?`, `M0`, `M1`, `P` (+ `S`,`R`,`C` в режиме `M0`) |
| Телеметрия | `RPM SET DUTY ERR ADC VS FLT` | + `PWM F EN` |
| Сторож связи | `UART_LOST` (нет команд > 5 с) | `PWM_LOST` (PB8 = 1 без ШИМ > 500 мс) |
| Роли входов ADC | `A0` = V_low, `A1` = V_supply | **перекрёстно**: `A1` = V_low, `A0` = V_supply (§18.7) |

### 18.7. Плата варианта GRBL: перекрёстная разводка входов A0/A1

Плата этого варианта разведена под разъёмы grblHAL, и при разводке пришлось
**поменять выводы A0 и A1 местами** относительно базовой платы. Физически это
значит, что делитель низкой стороны мотора попадает на `A1`/`PA1` (ADC1_IN1),
а делитель питания — на `A0`/`PA0` (ADC1_IN0).

Прошивка компенсирует это на этапе сборки: роли входов переставляются макросом
`BEMF_ADC_CH_SWAP` (`Core/Inc/bemf.h`), который по умолчанию равен
`BEMF_CTRL_GRBL`:

| Сборка | `BEMF_ADC_CH_SWAP` | Вход «низкая сторона» | Вход «питание» |
|---|---|---|---|
| `uart` | `0` | `A0` (PA0, IN0) | `A1` (PA1, IN1) |
| `grbl` | `1` (**эта плата**) | `A1` (PA1, IN1) | `A0` (PA0, IN0) |

Что при этом **не** меняется:

* масштаб и расчёт напряжений — на обоих входах одинаковые делители 10к/2к;
* порядок ячеек буфера DMA — он всегда соответствует рангам
  (`BEMF_ADC_RANK_LOW = 1` → `adc_dma_buf[0]`, `BEMF_ADC_RANK_SUPPLY = 2` → `[1]`);
* телеметрия и защиты работают с **ролями** («питание», «низкая сторона»), а не с
  номерами пинов, поэтому `VS`, `ADC`, `FLT` и проверка `SUPPLY_LOW` не изменяются.

Переопределить решение можно ключом сборки (полезно для старой платы или для
проверки):

```powershell
powershell -ExecutionPolicy Bypass -File _build\build_main.ps1 -Mode grbl -AdcSwap off  # как на базовой плате
powershell -ExecutionPolicy Bypass -File _build\build_main.ps1 -Mode grbl -AdcSwap on   # явно включить
powershell -ExecutionPolicy Bypass -File _build\build_main.ps1 -Mode grbl               # auto = on
```

То же самое «вручную»: дописать в `$DEFS` файла `_build\build_main.ps1` ключ
`-DBEMF_ADC_CH_SWAP=0` (или `=1`).

**Как убедиться, что прошито то, что нужно.** GRBL-сборка с включённой перестановкой
печатает при старте строку `ADC swap: A1 = V_low, A0 = V_supply`. Если перестановка
не соответствует плате, телеметрия `?` покажет `VS≈0` (на «питание» попал делитель
низкой стороны, который в измерительной паузе почти на массе), а затем пойдёт авария
по недостоверным замерам — в этом случае пересоберите прошивку с другим `-AdcSwap`.
